## Interpretation

The production fix prevented factory-default overwrite in at least one code path, but the persisted object being reloaded is still failing validation and getting discarded. Once that happens, the app falls back to blank state and refuses to auto-save defaults over real data.

So:
- ✅ New bundle is deployed
- ✅ Clean start works
- ✅ Initial parse + manual correction work in-session
- ❌ Reload persistence is still broken
- ❌ TB-003 fails
- ❌ TB-002 regression also fails in this flow after reload loss

## Recommendation

Investigate persisted payload shape for `omni-intake-v1` / `omni-intake-cross-page` immediately before reload. The failing fields named by validation strongly suggest incomplete `crmData` reconstruction during reload/merge:
- `crmData.address.lat`
- `crmData.address.lng`
- `crmData.rawText`
- `crmData.parsedAt`
- `crmData.confidence`

Likely issue: reload merge path is still producing a partial CRM object that does not satisfy the current schema, causing full intake restoration to fail.
