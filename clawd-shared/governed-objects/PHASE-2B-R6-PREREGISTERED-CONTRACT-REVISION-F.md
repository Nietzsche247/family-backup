### 10.8. Deterministic UTC Timestamp Generation (NEW — fixes PRODUCER-TIMESTAMP-001)

The `timestamp` field (field 20) in every producer receipt MUST be generated by deterministic runtime code that:

1. Obtains the current instant from the system clock
2. Converts to UTC (not local time)
3. Serializes as canonical ISO 8601 with `Z` suffix

**Required implementation in producer work packet:**

The producer's work packet MUST include this exact instruction for generating the receipt timestamp:

```
To generate the receipt timestamp, run this command and use its output exactly:
powershell -NoProfile -Command "[System.DateTime]::UtcNow.ToString('yyyy-MM-ddTHH:mm:ssZ')"
```

Or equivalently via Node.js:
```
node -e "console.log(new Date().toISOString())"
```

The producer MUST use the output of one of these commands as the `timestamp` value. The producer MUST NOT:

- Manually construct a timestamp string from observed wall-clock time
- Use local time with a `Z` suffix
- Use `Get-Date -Format` without explicit UTC conversion
- Omit the `Z` suffix
- Use any format other than `yyyy-MM-ddTHH:mm:ssZ` or full ISO 8601 with `Z`

**Defect reference:** PRODUCER-TIMESTAMP-001 — R5 Program B produced `2026-09-05T10:48:33Z` (local Arizona time with Z suffix) instead of `2026-09-05T17:48:33Z` (correct UTC). The gate correctly rejected this because it preceded the experiment dispatch time.

### 10.9. Timestamp Fixture Tests (NEW — 6 tests)

Before R6 freeze, the following timestamp fixtures MUST all produce the correct result:

| # | Fixture | Input | Expected | Validates |
|---|---|---|---|---|
| 1 | America/Phoenix → correct UTC | `10:48:33 MST` wall clock | Timestamp contains `17:48:33Z` (UTC) | UTC conversion |
| 2 | Second non-UTC timezone → correct UTC | Any non-UTC timezone | Correct UTC equivalent | Generality |
| 3 | Local-time-with-Z → REJECTED | `2026-09-05T10:48:33Z` when actual UTC is `17:48:33Z` | Gate FAIL (timestamp < experiment start) | R5 exact failure reproduction |
| 4 | Timestamp >= experiment dispatch | Valid UTC timestamp after dispatch | Gate PASS | Temporal ordering |
| 5 | Ambiguous timestamp without offset → REJECTED | `2026-09-05T10:48:33` (no Z, no offset) | Gate FAIL (missing timestamp format) | Format enforcement |
| 6 | Canonical UTC serialization stable | Two consecutive calls | Same format, monotonically increasing | Stability |

**Fixture 3 is mandatory:** It reproduces the exact R5 failure class:
```
Experiment dispatch: 2026-09-05T17:41:18Z
Producer local time: 10:48:33 AM America/Phoenix
INVALID receipt:     "timestamp": "2026-09-05T10:48:33Z"
CORRECT receipt:     "timestamp": "2026-09-05T17:48:33Z"
Gate result:         FAIL (10:48:33Z < 17:41:18Z)
```

All 6 fixtures must produce the correct result before freeze.
