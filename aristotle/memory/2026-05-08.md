## Gateway/Ngrok Outage Post-Mortem (May 5–8)

### What happened
- May 5: Desktop Commander session built Scheduled Tasks for Aristotle Gateway + Ngrok
- Tasks verified working end-to-end during live test
- Tasks never fired again — `AtLogon` trigger doesn't fire on sleep/wake/lock/unlock/fast-startup
- Ngrok was down for 3 days (nothing launching it)
- Gateway survived by accident — Aaron manually clicking `aristotle start.cmd` to revive
- Each manual click spawned a new supervisor with infinite restart loop → 6 zombies fighting over port 18792
- Bonjour name conflicts in logs = evidence of multiple gateways advertising simultaneously

### Root causes
1. `AtLogon` trigger limitation — not a reliable persistence mechanism on Windows
2. No de-duplication on manual launches — each `start.cmd` click = new supervisor tree
3. No watchdog or self-healing for the tasks themselves

### Fixes applied (by Desktop Commander session, May 8)
1. **Periodic triggers added:** Both tasks now have AtLogon + every-5-minute trigger
2. **De-dup logic:** Wrappers kill zombies before starting; `MultipleInstances=IgnoreNew` prevents concurrent runs
3. **Ngrok wait timeout:** 60s → 120s (gateway takes ~32s to bind on this machine)
4. **Recovery script built:** `C:\Users\aaron\clawd-shared\aristotle_recover.py` (475 lines, stdlib only)
   - `aristotle-recover.cmd` — cmd launcher (double-clickable)
   - `--check` = diagnose only
   - `--soft` = only restart broken parts (5-30s)
   - no flags = full hammer (kill everything, restart from scratch, 60-90s)
   - `-v` = verbose (combinable)
