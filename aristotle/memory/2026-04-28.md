## BINDING FRAMEWORK UPDATE (April 28, Aaron directive)

### Empirical Completion Definition (PERMANENT)
Complete state = empirical proof of intended behavior under real or near-real operating conditions. Nothing else qualifies.
- Structural tests (registration, wiring, hooks) prove Integrated, NOT Complete
- Type-check passing proves Verified, NOT Complete
- Synthetic mocked tests sit between Integrated and Complete
- "All pieces in place" reasoning is NOT evidence
- Confidence is NOT evidence

### Updated Four-State Model
| State | Definition | Verification |
|-------|-----------|--------------|
| Ported | Code in place | File presence, no truncation |
| Verified | Code compiles, types resolve | Full-codebase tsc passes |
| Integrated | Wiring connects, structural tests pass | Structural test suite passes |
| **Complete** | **Empirical proof of intended behavior under real/near-real conditions** | **Behavioral test: actual agent performing intended task** |

### New Lessons
- L16: Structural integration tests ≠ behavioral integration tests. Complete requires behavioral validation under operating conditions.
- L17: The work to claim completion is always lighter than the work to prove it. This asymmetry is permanent. Confidence is not evidence. Reasoning is not evidence. Test passing is evidence only when the test validates the right thing.
- L18 (meta): Three consecutive L8 occurrences = structural tendency, not single lesson. Future framework updates anticipate L8 slippage at every state boundary with explicit empirical evidence requirements.
