# CalculatorDefect — DEF-001

## Geocoder Normalization Overwrites Canonical Project Address

| Field | Value |
|-------|-------|
| `defect_id` | DEF-001 |
| `track` | B — Intake Trigger Chain + Jurisdiction |
| `title` | Geocoder normalization overwrites canonical Project Address and triggers a second geocode cycle |
| `reported_by` | Plato (engineering trace), escalated by Aaron |
| `owner` | Plato (fix), Empiricus (validation) |
| `status` | `fix-verified` |
| `severity` | `critical` |
| `expected_behavior` | Project Address remains as entered/corrected by the designer. Geocoder produces a normalized version stored separately as derived/reference data. No second geocode cycle fires. |
| `observed_behavior` | Geocoder normalizes the address and writes the normalized version back into the canonical Project Address field, overwriting the designer's input. This triggers the reactive chain again, causing a second geocode cycle. |
| `reproduction_steps` | 1. Enter or paste an address into Project Address. 2. Observe geocoder fires and normalizes address. 3. Normalized address overwrites Project Address field. 4. Second geocode cycle triggers from the overwrite. |
| `fix_description` | Option A: coordSource guard fix. Tags coordinate origin when written by forward geocode, prevents reverse geocode from firing on forward-geocode-written coords. Commit e0455d7 on OmniCalculator. |

Street number changed (8880→8881) = different property. All downstream data (site intel, property, jurisdiction) ran against wrong parcel. No UI indication of overwrite. | `notes` | **Provisional design recommendation (Aaron):** Canonical Project Address should remain authoritative. This directly relates to Track B Trigger-Chain Law §5: "Downstream modules may derive and display address-related data, but may NOT silently replace the canonical Project Address." |

## Violation Reference

This defect violates **Canonical Trigger-Chain Law §1** (Project Address is the canonical field), **§3** (manual correction is authoritative — overwrite negates it), and **§5** (downstream modules may not silently replace canonical shared state).
